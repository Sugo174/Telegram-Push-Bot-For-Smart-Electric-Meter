# Запуск Smart Meter PUSH Notifications в Windows

[English version](RUN_WINDOWS.md) · [Описание проекта](../README.ru.md)

## Перед началом

Нужны:

- установленный Python 3.14;
- исходники проекта;
- токен Telegram-бота;
- параметры SOCKS5-прокси;
- доступность сервера из сети счётчиков.

Команды ниже выполняются в PowerShell из корня проекта.

Если это обновление существующей установки, сначала выполните
резервное копирование рабочей базы и `.env`.
Не заменяйте их файлами другой установки.

## Первая установка

Создайте отдельное окружение и установите зависимости:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте `.env` по образцу `.env.example`.
Заполните токен бота, Telegram ID администратора,
адрес прокси и TCP-порт PUSH-сервера.

Не публикуйте `.env` и не отправляйте его вместе
со снимками экрана или обращениями об ошибке.

## Запуск бота

В первом терминале выполните:

```powershell
.\.venv\Scripts\python.exe app.py
```

Дождитесь сообщения `Bot started`.
Бот создаёт необходимые таблицы базы при запуске.

## Запуск PUSH-сервера

Во втором терминале из той же папки выполните:

```powershell
.\.venv\Scripts\python.exe push_server.py
```

Дождитесь сообщения `PUSH server started on port ...`.

Оба терминала должны оставаться открытыми.
Для штатной остановки нажмите Ctrl+C в каждом из них.

Запускайте только один экземпляр бота с данным токеном
и один PUSH-сервер на выбранном порту.

## Проверка работы

1. Укажите в счётчике доступный адрес сервера и TCP-порт,
   совпадающий с `PUSH_SERVER_PORT`.
2. Отправьте `/start` своему боту в Telegram.
3. Выберите язык и подключите прибор либо группу.
4. Отправьте тестовый PUSH с прибора.
5. Проверьте приём пакета в терминале сервера
   и доставку уведомления в Telegram.

Успешная ручная отправка проверяет доставку тестового пакета.
Автоматическую отправку при возникновении события
необходимо проверять отдельно.

## Совместный запуск и ярлык

`start_all.bat` открывает окна сервера и бота,
используя команду `python` из окружения запуска.

Если зависимости установлены в `.venv`, сначала активируйте
это окружение в терминале:

```powershell
.\.venv\Scripts\Activate.ps1
.\start_all.bat
```

Если PowerShell запрещает активацию, используйте прямые
команды запуска из предыдущих разделов.

`setup_windows.bat` создаёт ярлык на рабочем столе,
но не устанавливает Python и зависимости.

Запуск ярлыком не гарантирует использование `.venv`.
Если появляются ошибки отсутствующих модулей,
используйте прямой запуск через `.venv\Scripts\python.exe`.

## Обновление

1. Остановите сервер, бота и менеджер групп.
2. Сохраните резервные копии рабочей базы SQLite и `.env`.
3. Обновите файлы программы, сохранив рабочую базу и настройки.
4. Установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

5. Запустите бота и дождитесь инициализации.
6. Запустите PUSH-сервер.
7. Проверьте архив, подключение прибора и новое тестовое событие.

В репозитории используется `meter_events.db` рядом с `database.py`.
Если ваша установка использует другое имя или расположение,
сохраняйте и восстанавливайте фактически используемую базу.

## Диагностика доставки

### На сервере нет нового подключения

Проверьте адрес и порт назначения в приборе,
доступность сервера из сети прибора и правила межсетевого экрана.

Отсутствие записи о подключении само по себе
не позволяет определить причину: прибор мог не начать отправку
либо соединение могло не дойти до сервера.

### Подключение есть, но полного пакета нет

Сохраните сообщения о подключении, тайм-ауте и закрытии соединения.
Проверьте, передал ли прибор данные и соответствует ли транспортный
формат поддерживаемому сервером.

### Пакет принят, но уведомления нет

Проверьте:

- распознан ли серийный номер;
- зарегистрирован ли прибор;
- ненулевая ли маска событий;
- записано ли событие для пользователя;
- работает ли Telegram-бот;
- есть ли ошибки Telegram или прокси в терминале бота.

Наличие пакета в журнале сервера ещё не подтверждает
доставку уведомления в Telegram.

### Сообщения об отсутствующих таблицах базы

При первой установке сначала запустите `app.py`.
Убедитесь, что компоненты используют одну и ту же рабочую базу.

Не удаляйте существующую базу для устранения ошибки
без резервного копирования и выяснения причины.

## Обращение за помощью

Укажите версию или коммит программы, версию Python,
последовательность действий и время тестового события.

Приложите обезличенные строки из терминалов сервера и бота
за соответствующий период.

Не публикуйте токен бота, параметры доступа к прокси,
ключи групп, рабочую базу или полные производственные журналы.
